HTTP: 브라우저와 서버가 요청과 응답을 주고받는 규칙

HTTPS는 TLS로 보호되는 HTTP 통신

TLS: 통신을 보호하고 서버 인증서 확인에 사용되는 기술

암호화와 평문: 평문은 읽을 수 있는 원래 내용, 암호화된 데이터는 통신 중 내용을 그대로 읽기 어렵게 바뀐 데이터

인증서와 개인키: 인증서는 서버 신원과 공개키 정보를 담고, 개인키는 서버만 보유

PKCS12와 P12: PKCS12는 인증서와 개인키를 파일에 보관하는 형식, .p12는 확장자

keytool : JDK에 포함된 인증서 키 관리 프로그램

curl(컬) : 주소로 HTTP HTTPS 요청을 보내고응답을 확인하는 프로그램

공개키 : 공개, 인증서에 포함
개인키: 서버만 비밀로 보관해야함(이번 실습에는 .p12 파일에 보관)

(실습내용)
http:8081 => curl.exe --noproxy "*" -d "note=classroom"
http://127.0.0.1:8081/ #http 서버에 전송 요청(post 요청)

=> 와이어샤크에서 전송/응답 내용 : received: note=classroom
     평문으로 확인 가능 

---------------------------------------
https: 127.0.0.1:8443 => curl.exe --noproxy "*" -d "note=classroom" https://127.0.0.1:8443/
=> 인증서 검증 오류
* classroom-local.p12 인증서를 생성 (keytool 이용) => 신뢰성이 떨어짐
=> -k 옵션 : 인증서 검사 건너 뜀
curl.exe --noproxy "*" -d "note=classroom" https://127.0.0.1:8443/

결과 : HTTP는 요청 내용을 전송 중에 읽을 수 있지만 HTTPS는 TLS로 통신 내용을 보호하며 인증서를 통해 서버 신원을 확인함
